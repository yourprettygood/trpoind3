# Электронный учебный кабинет преподавателя и студента

Информационный ресурс для организации учебного процесса, обеспечивающий структурирование дисциплин по темам и лекциям, контроль усвоения теоретического материала, прохождение тестирования и **последовательное открытие лекций на стороне сервера**.

Проект разработан в рамках **Индивидуального практического задания №3** (ТРПО / «Внедрение и поддержка компьютерных систем») в строгом соответствии с требованиями стандартов разработки (`GEMINI.md`).

---

## 🚀 Быстрый запуск в 1 шаг

### Способ 1. Автоматический запуск через скрипт (Windows)
Просто дважды кликните по файлу **`run.bat`** в корне проекта (или выполните в терминале):
```cmd
run.bat
```
Скрипт автоматически:
1. Проверит наличие установленного .NET SDK.
2. Проверит статус локальной службы PostgreSQL (`postgresql-x64-18`).
3. Запустит веб-сервер Kestrel на `http://localhost:5000`.
4. Автоматически откроет браузер со страницей авторизации.

### Способ 2. Запуск через консоль dotnet
```cmd
cd src/EduCabinet.Web
dotnet run --urls "http://localhost:5000"
```
После запуска откройте в браузере: [http://localhost:5000](http://localhost:5000)

> При первом запуске приложение **автоматически создаст необходимые таблицы** в PostgreSQL (`educabinet_db`) и предзаполнит базу демонстрационным курсом «Внедрение и поддержка компьютерных систем», темами, вопросами, тестами и тестовыми учётными записями.

## 🛠 Стек технологий

* **Платформа и язык:** .NET 8 / C# 12
* **Веб-фреймворк:** ASP.NET Core MVC (Razor Pages & Views)
* **СУБД:** PostgreSQL 18 (база данных `educabinet_db`)
* **ORM:** Entity Framework Core 8 / Npgsql
* **Безопасность и RBAC:** ASP.NET Core Identity (хеширование паролей, роли, сессионные куки)
* **Фронтенд:** Bootstrap 5, Bootstrap Icons, CSS3 Print Styles (`@@media print`, `.no-print`)
* **Тестирование:** xUnit, FluentAssertions

## 📌 Ключевые архитектурные особенности

1. **Серверная защита последовательного открытия лекций:**
   Студент не может перейти к следующей лекции, пока не выполнит обязательные условия по предыдущей:
   * ознакомление с теорией;
   * сдача контрольных вопросов;
   * прохождение теста с результатом не ниже заданного порога (по умолчанию $\ge 70\%$).
   Ограничение проверяется строго **на бэкенде** (`LectureAccessService`) — прямой ввод URL закрытой лекции блокируется.

2. **Изоляция пользовательских и служебных данных (GEMINI.md Rule 1):**
   Ответы студентов (`StudentAnswerText`, `SubmittedAt`) хранятся изолированно от резолюции преподавателя (`TeacherScore`, `TeacherFeedback`, `GradedAt`). Сохранение оценки преподавателем никогда не затирает и не меняет исходный текст обучающегося.

3. **Официальные печатные формы (GEMINI.md Rule 2):**
   * **Академическая справка успеваемости студента** (`/Student/GradeReport`)
   * **Сводная зачётно-экзаменационная ведомость группы** (`/Teacher/GroupReport`)
   Печатные формы содержат реквизиты учреждения, регистрационные номера, даты, таблицы с баллами, места для подписей экзаменатора/декана и место для печати («М.П.»). Навигация и кнопки скрываются директивой `@@media print { .no-print { display: none !important; } }`.

4. **Ручной допуск преподавателем:**
   Преподаватель в журнале группы может вручную разблокировать лекцию студенту с обязательным указанием причины (действие протоколируется в `AuditLog`).
